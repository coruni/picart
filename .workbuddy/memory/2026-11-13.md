# 2026-11-13

## 修复：上传 GIF 丢失动画

**根因**：`ImageProcessorService` 把动图（GIF 多帧）转码成 WebP 输出（`-original.webp` + 全部缩略图）。
动图 WebP 在微信小程序、旧版 iOS/Android 浏览器、部分图片 CDN 上只渲染第一帧，表现为「上传后动画丢失」。

**改动**：
- `src/modules/upload/image-processor.service.ts`
  - 新增 `isAnimated()`（GIF/WebP 多帧统一判断），替换原 `isAnimatedGif()`。
  - 动图 `original` 直接复用源文件，不再生成 `-original.webp`（不转码）。
  - 新增 `generateAnimatedThumbnail()`：缩略图沿用源容器格式（GIF→GIF），按宽度等比缩放（sharp 对多帧不支持 `fit: cover` 逐帧裁剪），无需缩小则直接 copy 源文件。
  - 新增 `resolveOutputFrameHeight()` / `getFrameHeight()`：多帧图片的 `height` 是拼接总高度，返回 `pageHeight`（单帧高度）。
  - 静态图原图宽高改用 `toFile` 实际输出信息，修正只限制单边时的错误尺寸。
  - 动图按需解码，避免长期持有源文件句柄（Windows 上会导致文件锁）。
- `src/modules/upload/upload.service.ts`：S3 流程跳过动图 original 的重复上传。
- `src/modules/upload/upload.controller.ts`：`GET /upload/config` 增加 `preserveAnimation` 与 `skipPrecompressMimeTypes: ["image/gif"]`，提示前端不要用 canvas 预压缩动图。
- `package.json`：jest 增加 `moduleNameMapper`（`^src/(.*)$` → `<rootDir>/$1`），此前 `src/...` 导入在测试中无法解析。
- 新增 `src/modules/upload/image-processor.service.spec.ts`（3 个用例），已通过；`tsc --noEmit` 通过。

**验证要点**：动图处理后 `pages` 与 `delay` 保留，缩略图尺寸为单帧（240×180 → 200×150），不再被拉伸。

## 修复：动图没有缩略图 / 列表页加载失败

**根因**：`applyAnimatedOutputFormat` 直接把 `metadata.loop` 透传给 `sharp.gif()`。
libvips 把「无限循环」读成 `65536`，而 sharp 只接受 `0..65535`，于是重编码路径抛
`Expected integer between 0 and 65535 for loop`，被 `processImage` 的 try/catch 吞掉 →
真实世界的 GIF（如 Wikimedia 上的动图）**thumb 缩略图根本没生成**，列表页取不到 `thumbnails.thumb`。

**改动**：
- `image-processor.service.ts`
  - 新增 `resolveAnimationOptions()` / `resolveAnimationDelay()`：`loop >= 65535` 归一化为 0（无限），
    `delay` 补齐/裁剪到与 `pages` 一致并夹到 0..65535。
  - 新增 `generateAnimatedPosterThumbnail()`：动图最小尺寸（index 0，即 `thumb`）输出**静态首帧 WebP**
    （`sharp(path, { pages: 1 })`，几 KB），列表/卡片用；`small` 及以上仍保留动画。
  - `processImage` 的缩略图循环改为 `config.sizes.entries()`，按 index 判断是否为封面尺寸。
- `config/upload.config.ts`：`UploadConfig.staticThumbForAnimated`，env `UPLOAD_ANIMATED_STATIC_THUMB=false` 可关闭。
- `upload.controller.ts`：`GET /upload/config` 返回 `imageProcessing.animated.staticThumb`。
- spec 扩到 4 个用例，含「loop=65536 的 GIF 也能生成缩略图」回归（用 NETSCAPE2.0 块打补丁构造）。

**验证**：Wikimedia 400×400/44 帧 GIF → thumb 为 3KB 静态 WebP（此前直接失败）；480×270/33 帧 → thumb 8KB。
`tsc --noEmit` + 4 个用例全绿。
