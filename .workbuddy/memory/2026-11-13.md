# 2026-11-13

## 修复：上传 GIF 丢失动画

**根因**：`ImageProcessorService` 把动图（GIF 多帧）转码成 WebP 输出（`-original.webp` + 全部缩略图）。
动图 WebP 在微信小程序、旧版 iOS/Android 浏览器、部分图片 CDN 上只渲染第一帧，表现为「上传后动画丢失」。

**改动**：
- `src/modules/upload/image-processor.service.ts`
  - 新增 `isAnimated()`（GIF/WebP 多帧统一判断），替换原 `isAnimatedGif()`。
  - 动图 `original` 直接复用源文件，不再生成 `-original.webp`（不转码）。
  - 新增 `generateAnimatedThumbnail()`：缩略图沿用源容器格式（GIF→GIF），按宽度等比缩放（sharp 对多帧不支持 `fit: cover` 逐帧裁剪），无需缩小则直接 copy 源文件。
  - 新增 `resolveOutputFrameHeight()` / `getFrameHeight()`：多帧图片的 `height` 是拼接总高度，返回 `pageHeight`（单帧高度）。
  - 静态图原图宽高改用 `toFile` 实际输出信息，修正只限制单边时的错误尺寸。
  - 动图按需解码，避免长期持有源文件句柄（Windows 上会导致文件锁）。
- `src/modules/upload/upload.service.ts`：S3 流程跳过动图 original 的重复上传。
- `src/modules/upload/upload.controller.ts`：`GET /upload/config` 增加 `preserveAnimation` 与 `skipPrecompressMimeTypes: ["image/gif"]`，提示前端不要用 canvas 预压缩动图。
- `package.json`：jest 增加 `moduleNameMapper`（`^src/(.*)$` → `<rootDir>/$1`），此前 `src/...` 导入在测试中无法解析。
- 新增 `src/modules/upload/image-processor.service.spec.ts`（3 个用例），已通过；`tsc --noEmit` 通过。

**验证要点**：动图处理后 `pages` 与 `delay` 保留，缩略图尺寸为单帧（240×180 → 200×150），不再被拉伸。
