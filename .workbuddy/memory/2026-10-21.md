## 大范围日志重构（console → LoggerUtil）

用户已在 P4 后提交了 `6926f620 feat: Implement comprehensive project optimization and static audit findings`，本批基于该提交。

结果：19 个文件 `+191 / -216`，`console.*` 从 164 处降到 **2 处**（仅剩 `src/scripts/seed-points.ts` 的 CLI 输出，保留合理）。`tsc --noEmit` 与 `nest build` 通过。

### 覆盖文件（18 个）
payment.service(43)、level-event.service(26)、points-event.service(21)、enhanced-notification.service(11)、article.service(10)、achievement-event.service(9)、notification-event.service(7)、message.gateway(7)、comment.service(6)、achievement.service(5)、points.service(3)、order.service(3)、user-decorator.util(3)、decoration-event.service(2)、article-presentation.service(2)、commission.service(2)、user.service(1)、sanitize.util(1)。

### 转换规则
- `console.log|info` → `LoggerUtil.info(msg, "Ctx")`；`warn`/`debug` 同理
- `console.error("msg:", error)` → `LoggerUtil.error("msg", error, "Ctx")`（**带栈**，原实现只丢了 error.message）
- `console.error("msg:", err.message)` → 同样升级为传整个 error，保留栈信息（19 处）
- `console.error("msg")` → `LoggerUtil.error("msg", undefined, "Ctx")`（注意 `LoggerUtil.error` 第二参是 error 不是 context，必须占位）
- 多参数：标量并入模板字符串；对象走 `LoggerUtil.info(msg, ctx, obj)` 由 LoggerUtil 序列化（`${result}` 会变 `[object Object]`，已单独修正）
- 多行 `console.log(\n ... \n)` 合并为单行调用

### 踩坑记录（重要）
1. **`LoggerUtil.error` 签名是 `(message, error?, context?)`**，与 `info/warn/debug` 的 `(message, context?, data?)` 不同。批量转换时把 context 当成 error 传会让日志 stack 显示成类名，必须显式 `undefined` 占位。
2. 模板字符串内多个附加参数被拼成 `${a, b, c}` 是**逗号运算符**，只会输出最后一个值；必须拆成 `${a} ${b} ${c}`。
3. 用脚本批量改代码时，`LoggerUtil.error(msg, error, "Ctx")` 被二次修正规则误判成两参，追加了多余的 `undefined` 导致 4 参编译错误；靠 `tsc` 才发现，说明**每步都必须编译验证**。
4. 对象插值（`${user?.config}`、`${result}`）在 console.log 里会展开，转成字符串模板后变 `[object Object]`，必须改走 data 参数。

### 保留
- `src/scripts/seed-points.ts` 的 2 处 console：独立 CLI 种子脚本，输出到终端更合适。
- `cache.util.ts` 日志里的 emoji（✅❌🧪📊）：未改动文案。
